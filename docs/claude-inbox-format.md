# Claude 반영 형식 (cm-update-v1)

Claude가 사건 작업을 마친 뒤 만드는 **반영 블록**의 형식이다. 앱 상단 「Claude 반영」 창에 붙여넣거나 `.cm.json` 파일로 골라 읽는다.
Claude는 Firestore에 직접 쓰지 않는다. 반영은 사용자가 검토 창에서 항목을 확인하고 「선택 n건 반영」을 눌러야 일어난다.

> 이 문서와 시험 자료의 사건, 당사자, 사건번호는 모두 가공이다. 저장소가 공개이므로 실제 사건 정보를 넣지 않는다.

## 1. 사건 연결 코드 (cm-binding-v1)

- 사건 화면 「수정」 옆 「연결 코드 복사」를 누르면 한 줄 JSON이 복사된다.
- Claude 사건 폴더 세션에 한 번 붙여넣어 두면, Claude가 그 사건의 반영 블록에 `cmCaseId`를 정확히 적는다.

```json
{"format":"cm-binding-v1","cmCaseId":"c1760000000000","caseNumber":"2026가단10000","title":"가나다 물품대금"}
```

- `cmCaseId`는 앱의 사건 id(문서 id)다. 사건을 고쳐도 바뀌지 않는다.
- 사건번호가 없거나 "—"이면 `caseNumber`는 빈 문자열이다.
- 연결 코드를 검토 창에 붙여넣으면 「연결 코드입니다」라고 알리고 읽지 않는다.

## 2. 묶음

```json
{
  "format": "cm-update-v1",
  "batchId": "261017-1432-k7q2",
  "createdAt": "2026-10-17T14:32:00+09:00",
  "source": { "folder": "가공 사건 폴더", "pc": "사무실" },
  "items": [ … ]
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| format | 필수 | `cm-update-v1` |
| batchId | 필수 | 묶음 id. 영문, 숫자, `-`, `_`만, 100자 이내. 묶음마다 새로 만든다 |
| createdAt | 선택 | 작성 시각(표시용) |
| source | 선택 | `folder`, `pc`, `session`만 쓸 수 있음(표시용) |
| items | 필수 | 항목 1~200건 |

- 묶음에 위 밖의 필드가 있으면 읽지 않는다.
- 이미 낸 묶음은 고치지 않는다. 정정은 새 `batchId`로 낸다.

## 3. 항목 공통 필드

| 필드 | 필수 | 설명 |
|---|---|---|
| id | 필수 | 항목 id. 영문, 숫자, `-`, `_`만, 120자 이내. 묶음 안에서 겹치면 안 됨 |
| cmCaseId | 필수 | 연결 코드의 사건 id. 없으면 오류(이름으로 추측하지 않음) |
| caseNumber | 권장 | 연결 코드의 사건번호. 앱 사건번호와 대조하고 다르면 오류(아래 대조 규칙) |
| op | 필수 | 아래 8종 중 하나 |
| basis | 권장 | 근거(검토 창에만 보이고 사건에는 저장하지 않음). 없으면 경고 |

- 날짜는 `YYYY-MM-DD`, 시각은 `HH:MM`(24시간, 한국시간).
- 문자열은 한 칸에 2,000자까지.
- op별로 정해진 필드 밖의 필드가 있으면 오류.
- 선택 필드는 빼거나 `null`로 둘 수 있다.
- 같은 `batchId`와 항목 `id`를 다른 내용에 다시 쓰면 오류다. 정정이나 추가는 늘 새 `batchId`로 낸다.
- 사건번호 대조 규칙(포함 비교는 하지 않음)
  - 일치: 공백만 뺀 전체 문자열이 같거나, 앱 칸을 `,` `/` `;` `·` 줄바꿈으로 나눈 번호 하나와 같음. 연결 코드는 앱 사건번호를 그대로 옮기므로 연결 코드를 다시 받으면 늘 맞는다.
  - 일부 일치(경고): 파일 쪽이 「연도+부호+번호」 하나이고 앱 칸의 글 속에만 있음(예: 앱 "2026가단1 외 1건", "2027나100 (원심 2026가단1)")
  - 불일치(오류): 그 밖의 경우

## 4. 항목 종류(op)

| op | 필수 | 선택 | 앱에 반영되는 모습 |
|---|---|---|---|
| brief.submitted | title, date | details | 같은 제목의 제출대기 서면을 제출 처리(없으면 새로 만들어 제출 처리) + 진행경과 "제목 제출" |
| brief.pending | title | date(작성일, 기본 오늘), details | 제출대기 서면 추가 |
| deadline | title, date | content | 기한(메모 분류 불변기간, 확인 안 함 상태) |
| todo | text | details, priority(`높음`·`보통`, 기본 보통), dueDate | 할 일(미완료) |
| hearing | date, type | time, place | 기일(장소는 기일 아래 줄에 표시) |
| progress | date, content | detail, activityType | 진행경과(유형 기본 기타) |
| call | date, title | detail, asClientRequest(true/false) | 진행경과 "[통화/상담] 제목 — 내용"(유형 통화) + asClientRequest면 의뢰인요청 메모 |
| memo | category, title | content, date(기본 오늘) | 메모 |

- `activityType`: `document`(문서 제출), `receipt`(서류 수령), `hearing`(기일), `call`(통화), `meeting`(회의), `review`(내부 검토), `ruling`(결정·판결), `payment`(정산), `other`(기타)
- `memo`의 `category`: `의뢰인요청`, `기일메모`, `공식결과메모`, `일반메모`. 불변기간은 `deadline`으로 보낸다.
- 서면 제목은 공백을 무시하고 비교한다("준비서면 (2)" = "준비서면(2)").
- 기일은 LBOX 캘린더가 넣지 않는 것(수사기관 조사 등)만 보내는 것이 원칙이다. 보낼 때는 기일 종류를 LBOX와 같은 말("변론기일" 등)로 쓴다.

## 5. 검토 창의 판정

| 판정 | 뜻 | 기본 선택 |
|---|---|---|
| 정상 | 검증 통과 | 선택됨 |
| 경고 | 반영할 수는 있으나 확인이 필요함 | 해제(노란 표시, 직접 골라야 함) |
| 오류 | 반영할 수 없음 | 고를 수 없음 |
| 이미 반영됨 | 같은 묶음의 같은 항목이 이미 들어감 | 고를 수 없음 |

- 오류
  - `cmCaseId` 없음, 앱에 없는 사건, 사건번호 불일치
  - 알 수 없는 op나 필드, 필수 값 없음, 날짜·시각 형식 오류, 2,000자 초과, 묶음 안 항목 id 중복
  - 같은 묶음·항목 id로 다른 내용이 이미 반영됨(묶음 id 재사용)
- 경고
  - 사건번호 대조 불가(파일이나 앱에 사건번호 없음), 사건번호 일부 일치, 종결 사건, 근거 없음
  - 지난 기한, 지난 기일, 지난 마감일, 오늘 이후 날짜의 제출·진행경과·통화
  - 같은 내용이 사건에 이미 있음(같은 날짜·내용의 진행경과, 같은 날짜·종류·시각의 기일, 같은 날 다른 기일, 같은 제목 서면, 같은 내용의 미완료·완료 할 일 등)
  - 같은 묶음 안에 같은 내용의 항목이 또 있음, 같은 묶음에서 제출 처리한 서면을 다시 제출대기로 넣음
  - 서면 제출인데 같은 제목의 제출대기 서면이 없음(새로 만들어 제출 처리)
- 이미 반영됨
  - 반영 기록(`users/{uid}/meta/claudeInbox`)에 그 묶음의 항목 id가 같은 내용 지문으로 있거나
  - 사건 안에 그 항목으로 만든 기록(`claude` 표시나 고정 id)이 있을 때
- 화면에서 정상으로 본 항목이 반영 직전 다시 검사할 때 경고로 바뀌었으면(그 사이 LBOX 기일이 들어온 경우 등) 넣지 않고 「상태가 바뀌어 건너뜀」으로 알린다.

## 6. 반영 방식 (중복·덮어쓰기 방지)

- 사건마다 바뀐 부분만 서버 최신 사건 문서에 얹는다(앱의 다른 저장과 같은 `saveCase` 대기열). 기존 항목과 사건 기본 필드(상태, 보수, 당사자)는 바꾸지 않는다.
  - 예외: `brief.submitted`는 같은 제목의 제출대기 서면을 제출 상태로 바꾼다. id가 겹치거나 비정상인 서면은 짝짓지 않고 새 서면을 만든다.
  - 항목 하나가 자기 새 항목(`cl:…`)과 짝지은 서면 밖을 바꾸게 되면 그 항목은 넣지 않는다.
- 저장 순간 보호(`src/claudeGuard.js`)
  - 검토 창은 화면 판본으로 계획을 세우므로, 저장 diff에 보호 정보(`diff.claude`)를 붙이고 저장 트랜잭션에서 서버 최신본과 반영 기록에 맞춰 다시 가린다.
  - 이 항목으로 만든 기록이 이미 있으면(다른 기기에서 먼저 반영하고 고친 경우) 덮지 않는다.
  - 반영 기록에 이미 있는 항목은 다시 만들지 않는다(사용자가 지운 항목을 되살리지 않음).
  - 서면 제출은 최신 서면이 아직 제출대기일 때만 제출 칸(상태, 제출일, 진행경과 연결, 표시)만 얹는다. 그 사이 제출됐거나 지워졌으면 건너뛴다.
  - 화면 겹쳐 보기와 서버 저장이 같은 규칙을 쓴다. 이 기기에 보관됐다가 앱을 다시 열어 보내는 저장도 같다.
- 새로 만드는 항목의 id는 `cl:<batchId>:<항목 id>`로 고정하고 `claude: { batchId, itemId, fp }` 표시를 붙인다.
  - `fp`는 파일에 적힌 항목 내용의 지문(근거, 사건번호, 항목 id 제외, 앱이 채운 기본값 제외)이다.
  - 서면 제출의 진행경과는 `…:tl`, 통화의 의뢰인요청 메모는 `…:memo`가 붙는다.
  - 같은 항목이 두 번 저장되어도 같은 id로 덮일 뿐 늘어나지 않는다.
  - 서면 제출이 기존 제출대기 서면을 쓸 때는 그 서면의 옛 제출 연결을 버리고 이번 진행경과(`…:tl`)로 새로 잇는다. 서면 메모는 비어 있을 때만 채운다.
  - 기존 서면에는 `claudeSubmit: { batchId, itemId, fp }` 표시를 붙인다. 서면 탭에서 제출 대기로 되돌려도 표시가 남아 같은 항목이 다시 반영되지 않는다.
- 반영 기록 `meta/claudeInbox`
  - `batches.<batchId>.at`: 마지막 반영 시각
  - `batches.<batchId>.items.<항목 id>`: `{ fp: 내용 지문, caseId: 넣은 사건 id }`
  - 사건 저장과 같은 트랜잭션에서 적는다(함께 되거나 함께 안 됨). 실제로 들어갔거나 이미 있던 항목만 적고, 다른 기기에서 처리되어 건너뛴 항목은 적지 않는다.
  - 묶음이 1,000개를 넘거나 문서가 약 60만 자를 넘으면 마지막 반영이 오래된 묶음부터 지운다. 지운 묶음도 사건 안 표시로 중복은 계속 막힌다.
  - 백업(내보내기) 대상에 들어 있다.
- LBOX 기일과의 관계
  - LBOX 동기화는 Claude가 먼저 넣은 기일(claude 표시, 캘린더 연결 없음)을 날짜와 종류("기일" 생략·띄어쓰기 무시)가 같고 시각이 같거나 한쪽이 비었으면 같은 기일로 보고 그 일정에 연결한다(따로 하나 더 만들지 않음).
- 앱이 자동으로 쓰는 메모 제목(「캘린더 업무 요약」)은 메모, 기한, 통화 메모 제목으로 쓸 수 없다(오류).
- 붙여넣은 글은 전체 → 코드 상자 안 → 첫 `{`부터 끝 `}`까지 순서로 읽는다. 항목 글 속의 ``` 는 그대로 둔다.
- 서버 판본을 받기 전(「서버 확인 중…」)에는 「Claude 반영」 버튼과 반영 버튼이 막힌다.
